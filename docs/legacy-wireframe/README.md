# Legacy wireframe (archived)

This directory holds the original vanilla-HTML/JS wireframe that was used as
the visual reference when porting the UI to Leptos. **It is not built and
not loaded by any code path.**

> **`api-manifest.json` is historical and superseded.** It was an early
> hand-authored sketch of the REST surface and contains paths that no
> longer exist (e.g. `/cities/:id/citizens`, `PATCH /cities/:id/rename`,
> `/tech/queue`, `POST /map/overlays/:id/toggle`, `/diplomacy/civs/:id/action`)
> and omits paths that do (e.g. `/registry`, `/cities/:id/focus`, the
> `DELETE` variants of `/tech/research` and `/civics/research`). The
> canonical, source-generated description of the REST API is
> [`book/src/multiplayer/openapi.json`](../../book/src/multiplayer/openapi.json),
> regenerated by
> `cargo run -p open4x-server --features openapi --bin gen-openapi`. The
> human-readable companion is
> [`book/src/multiplayer/rest-api.md`](../../book/src/multiplayer/rest-api.md).

The live web client is `open4x-client-web` (a Leptos/wasm32-only cdylib)
which consumes `open4x-sdk`. Both ride on the same wire types declared in
`open4x-protocol::v1::web::*`.

## Why keep this directory at all?

- The JSON files (`*.json`) document the *data shapes* the wire types in
  `open4x-protocol::v1::web` mirror. If we extend a screen, this is the
  design reference.
- The HTML is a working visual mock. When porting a new tab, screenshot it
  for parity.
- Lifting & shifting it elsewhere (as a static screenshot or stripped
  Markdown) is a follow-up task once we no longer need the JSON shapes.

## Mapping wireframe → REST

Every `fetch("foo.json")` in the wireframe maps to a `/api/v1/*` GET. For
the current mapping, consult the OpenAPI spec or the
[REST API reference](../../book/src/multiplayer/rest-api.md). The
`HANDOFF.md` here is kept verbatim from the design session and may
disagree with the live router — trust the OpenAPI spec when they conflict.
